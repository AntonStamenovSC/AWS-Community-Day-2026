      Licensing and migration risks

      • SQL Server Web edition. cust1, cust4 and cust3 run Web edition. Under Microsoft's terms, Web edition is only licensed for public, internet-facing web workloads, and RDS applies the same rule. If these back-office databases have to move to Standard edition, the RDS SQL Server cost for cust1 rises to about /month.
      • RDS for SQL Server is licence-included only. You can't bring your own licence (RDS Custom for SQL Server allows it). Its Standard edition licence costs more per hour than the same licence on EC2, which is why cust2 goes up on RDS SQL Server.
      • PostgreSQL means code changes. T-SQL stored procedures, SQL Agent jobs, linked servers and any SSIS/SSRS work have to be rewritten or replaced. Babelfish for Aurora PostgreSQL can shorten this, but Aurora pricing isn't modelled here.
      • Fargate Linux needs a .NET port. APP-A, APP-B and APP-C run on Windows today. Linux containers need .NET 8+ with no Windows-only dependencies. Fargate Windows avoids the port but costs the most of any option.
      • RabbitMQ needs persistent state. Run it on Fargate with EFS, or use Amazon MQ (about $25–60/month per broker, not included).
      • UAT on RDS SQL Server Express is limited to 10 GB per database. Anything bigger needs Web or Standard edition at higher cost.
      • Not included: Savings Plans or Reserved Instances (none are in use today; either would lower every option), data transfer, CloudWatch Logs for containers, and the 20% UK VAT / tax line.

      Method & data notes

      • Allocation data: Cost Explorer GetCostAndUsage on the payer account, grouped by LINKED_ACCOUNT and SERVICE, using UnblendedCost with monthly granularity. Net amortised cost is identical because there are no Savings Plans or RIs. Totals include Tax and Support, and are net of the distributor discount (reconciled against RECORD_TYPE).
      • September 2026 covers 1–24 Sep only (month-to-date). Use August 2026 as the run rate.
      • Tag allocation uses the cost-allocation tags env, component and customer, which were activated in June 2026, so there is no tag data before June.
      • cust1 and cust2 detail come from the tenant profiles (acme-cust1-… and acme-cust2-ReadOnlyAccess-333344445555): Cost Explorer by Name tag and usage type, EC2 DescribeInstances/Volumes/VpnConnections, and 30 days of CloudWatch CPU plus CWAgent memory on the app server.
      • What-if pricing comes from the AWS Price List API (on-demand, Sep 2026) for eu-west-2, eu-central-1 and eu-central-2. EC2 licence cost = (Windows rate − Linux rate) and (Windows+SQL rate − Windows rate). The RDS SQL Server licence is the RDS SQL Server price minus the RDS PostgreSQL price for the same instance class, so it includes Windows. Operation codes in Cost Explorer identified the editions: RunInstances:0202 = SQL Web, :0006 = SQL Standard, :0002 = Windows only; RDS CreateDBInstance:0011 = SQL Web.
      • Right-sizing (Fargate ARM option) is measured for cust1 and cust2. cust1's app server has a p95 CPU of about 1 of 8 vCPUs. cust2's app server has a p95 of 1.6 of 4 vCPUs, and cust2 UAT runs about 420 h/month at 60% CPU, so it is not downsized. cust3, cust4 and Product are assumed at 50% of current size, with UAT and test running 260 h/month (12 h × 5 days). Please validate these against each account's metrics before committing.
      • Storage: cust1 volumes come from live EC2 data. cust2 comes from live volume data (DB1 needs 400 GB on RDS) plus Aug-2026 EBS and snapshot actuals by Name tag. cust3 EBS figures are Aug-2026 actuals by Name tag. cust4 DB storage is assumed at 150 GB. RDS automated backups are assumed to fit within the free allowance (100% of provisioned storage), which lets the backup EBS volumes be retired.
